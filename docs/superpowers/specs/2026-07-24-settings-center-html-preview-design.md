# 设置中心三方案 HTML 预览设计

## 目的与边界

先以一个离线单文件 HTML 比较三种设置中心布局，再决定是否移植到生产 React。预览只处理三件事：压缩设置页标题区、把五个内部设置分类改为顶部横向导航、修复“关于”页信息卡片的文字溢出。它不修改 `src/`、`public/`、Tauri、Rust、路由、保存逻辑或应用主导航。

预览文件固定为：

`D:\Project\notes\.codex-research\tauri-react-ui\vedionotes-settings-center-concept.html`

该文件使用内联 CSS、内联 SVG 和少量原生 JavaScript，无网络依赖，不导入 React、HeroUI、现有生产 CSS 或 Tauri bridge。

## 统一预览框架

- 保留完整桌面上下文：现有浅色窗口标题区、220px 应用主导航和设置主内容。
- 应用主导航仅作视觉参照，不改变其结构，也不重新加入已删除的品牌或工作区模块。
- 顶部提供独立的“方案 A / 方案 B / 方案 C”切换器；它只控制设置中心内部布局。
- 三种方案共用相同的设置数据、关于页卡片和五个内部分类，避免内容差异干扰布局比较。
- 五个分类顺序固定为：外观、语音转文字、AI 接入、数据管理、关于。
- 五个分类可点击切换，使用 `role="tablist"`、`role="tab"`、`aria-selected` 和键盘焦点样式。
- 默认打开“关于”，以便直接检查卡片断行和空间利用。
- 提供“正常内容 / 长文本压力测试”开关；压力数据覆盖长组件名、状态枚举、SemVer、SPDX 许可证、SHA、URL、Windows/UNC 路径和中英混排。
- 预览中的业务按钮不执行下载、连接、文件选择、删除或外部打开，只呈现禁用或说明状态。

## 共同视觉规格

### 紧凑标题区

- 根内容区沿用现有浅色、圆角、绿色点缀，不改主色系。
- 设置页整体顶部内边距约 20–24px，标题区底部内边距约 12px。
- `SETTINGS` 与 `设置` 的间距约 2–4px；`设置` 保持约 32–34px、行高约 1.08，不做小标题化处理。
- 说明文字紧随标题，段落外边距清零；标题区与内部导航间距约 12px。
- “当前：关于”作为轻量状态胶囊保留，但不能增加标题区高度。

### 关于页安全卡片

- 所有动态文本容器使用 `min-width: 0`、`max-width: 100%`、`overflow-wrap: anywhere` 和 `word-break: break-word`。
- 运行组件卡片头部采用可收缩的内容列与不可挤压但允许自身断行的状态标签；窄容器时状态标签换到下一行。
- 卡片正文使用 12–14px 字号和 1.45–1.6 行高；不使用 absolute/fixed 放置文字。
- 运行组件网格依据设置内容容器而不是整个 viewport 响应：空间足够时两列，否则单列。
- 版本信息由固定 320px 侧栏改为弹性列；空间不足时堆叠到运行组件下方。
- 本地目录显示真实布局形态的路径示例与操作按钮，路径可以逐段换行；明确注明生产当前只显示目录操作按钮。
- 第三方来源的 commit、许可证、URL 和说明均可断行，不裁剪、不省略核心信息。
- 卡片允许由内容撑高，并设置适度最小高度以保持同排节奏，不设置固定高度。

## 三种导航方案

### 方案 A：圆角分段卡片（推荐）

- 紧凑标题区下方是一张独立的圆角导航卡片。
- 桌面五项等宽单行排列；选中项使用白色/浅绿色胶囊、细边框和轻阴影。
- 内容卡片位于导航卡片下方，层级最清楚，也最接近当前 VedioNotes 视觉语言。
- 容器变窄时导航自身横向滚动，页面不产生横向溢出。

### 方案 B：轻量下划线标签

- 去掉导航外层卡片，只保留一条横向标签栏和底部分隔线。
- 选中项使用绿色文字、较高字重和短下划线；未选中项保持低对比。
- 纵向占用最小，但视觉上比当前圆角卡片体系更偏传统网页设置。
- 窄容器同样只让标签栏横向滚动。

### 方案 C：标题与分类同一行

- 桌面宽度下，紧凑标题位于左侧，五项圆角分类位于右侧，同处一个头部容器。
- 这是最省垂直空间的方案，但标题和导航会竞争横向空间。
- 当设置内容容器不足时，分类栏整体换到标题下方并可横向滚动；不把五项硬压成过小按钮。

## 响应式与验收

预览至少验证以下三档：

- 1280×800：应用侧栏展开，五项在 A/B 中一整行，C 的标题与导航同一行。
- 1024×760：应用侧栏展开，内容卡片根据容器宽度降列，页面无横向溢出。
- 820×720：应用侧栏折叠为 88px；内部标签栏可滚动或在 C 中落到第二行，关于卡片全部单列。

每档都检查：

1. 标题区明显短于当前生产截图，且“设置”仍具有一级标题权重。
2. 五项顺序、选中态和点击切换正确。
3. 页面 document/body 不横向溢出。
4. 卡片自身 `scrollWidth <= clientWidth`，长文本不越过边框。
5. 状态标签不覆盖标题，版本、许可证、SHA、URL 和路径均可读。
6. 方案切换不改变内容数据，便于直接比较导航结构。

## 后续生产移植边界

用户选定方案后，生产实现继续使用现有 HeroUI `Tabs` 的 `selectedKey/onSelectionChange` 与五个业务 Tab 组件。只允许调整 `CipherSettingsShell.tsx` 的内部导航容器、`AboutTab.tsx` 的安全类名/局部结构、`cipher-settings.css` 及对应测试；不重写设置状态、平台适配层或保存行为。
